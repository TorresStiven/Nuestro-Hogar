# Visión del proyecto

**Proyecto:** Nuestro Hogar
**Tipo:** Aplicación web
**Estado:** Desarrollo inicial (versión 0.1)
**Responsable:** Stiven Torres
**Año:** 2026

## Propósito

Nuestro Hogar busca facilitar la organización cotidiana y la conservación de
recuerdos de las personas que comparten un hogar. La herramienta debe hacer más
sencilla la coordinación de actividades sin convertir la convivencia en una
obligación ni en una competencia.

> Nuestro Hogar no existe para enseñarnos a convivir, sino para ayudarnos a
> construir, recordar y disfrutar el hogar que estamos creando juntos.

La idea se resume en tres principios:

1. **Construir:** organizar y desarrollar juntos el espacio compartido.
2. **Recordar:** conservar experiencias y momentos importantes.
3. **Disfrutar:** hacer que las actividades cotidianas sean más sencillas.

## Personas a quienes está dirigido

La aplicación está pensada para parejas, familias, compañeros de vivienda y
otras personas que comparten un espacio y quieren organizar sus actividades en
un sitio común.

## Objetivo académico

La primera versión permite practicar HTML, CSS y JavaScript mediante páginas
relacionadas, navegación, manipulación del DOM y persistencia local. También
sirve para comprender cómo se pueden separar las responsabilidades de una
aplicación web.

## Alcance por generaciones

### Primera generación: MVP local

Es la etapa actual. La aplicación funciona en el navegador, sin backend. Usa
`localStorage` para datos estructurados e IndexedDB para fotografías. No ofrece
sincronización entre dispositivos.

### Segunda generación: aplicación dinámica

Como posibilidad futura se contempla un frontend modular, una API y una base de
datos centralizada. Angular, TypeScript, Node.js, Express y PostgreSQL o MySQL
son alternativas por evaluar, no dependencias de la versión actual.

### Tercera generación: plataforma para hogares

A largo plazo se podrían explorar cuentas, hogares con varios integrantes,
invitaciones, permisos, sincronización, notificaciones y una aplicación web
progresiva. Estas ideas requieren definir primero necesidades de privacidad y
seguridad.

## Criterios para crecer

- Incorporar funcionalidades a partir de necesidades reales.
- Mantener módulos con responsabilidades claras.
- Conservar una navegación y una experiencia visual coherentes.
- Dar respuestas claras ante acciones y errores.
- Tratar los datos personales con privacidad y responsabilidad.
